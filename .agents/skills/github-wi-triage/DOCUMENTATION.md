## Step 1 – Understand the Need

Determine:

- Who is the audience?
- What question should the documentation answer?
- Why is new documentation needed?
- Is the information already documented elsewhere?
- Should existing documentation be updated instead?

---

## Step 2 – Define Success

Document:

- What readers should be able to do after reading it.
- What information must be included.
- Examples that should be provided.
- Related documentation that should be updated.

---

## Step 3 – Produce a Documentation Plan

Include:

- Documents to create or modify
- Sections to update
- Required screenshots or diagrams
- Code examples
- API references
- Cross-links to existing documentation
- Validation steps

---

## Step 4 – Adversarial Review

Spawn an adversarial reviewer.

Challenge the proposal by asking:

- Is the documentation understandable by its intended audience?
- Is anything missing?
- Are assumptions explained?
- Is duplicate documentation being created?
- Are examples sufficient?
- Could the structure be improved?

---

## Step 5 – Refine

Update the documentation plan based on the review.

---

## Step 6 – Publish

Post the documentation plan as a comment on the GitHub issue.

The comment should contain:

1. Audience
2. Documentation goals
3. Proposed changes
4. Validation strategy
5. Outstanding questions
